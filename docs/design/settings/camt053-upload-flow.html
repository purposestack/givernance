Upload micro-state journey

All five steps of the camt.053 upload lifecycle, plus four terminal result variants. Every state is rendered on this page so the developer can implement them without guessing transitions.

Five states (§5.1)

1. Idle — empty zone, awaiting drop or click
2. Dragging — visual reinforcement on drag-enter
3. Uploading — multipart in flight, cancel-able
4. Processing — server-side: pending → imported → processing → processed (polled every 2 s)
5. Result — four terminal variants below

Polling cadence

After upload completes, the UI polls GET /v1/camt-statements/:id every 2 s for up to 5 minutes. The status pill animates from pending → imported → processing → processed; on failed the result panel renders the error variant.

Result variants

✓ Success — counters + CTA to review queue
✗ XSD invalid — file isn't ISO 20022 camt.053
✗ Foreign IBAN — file is for a different tenant bank account; offer to switch tab
⚠ Duplicate — same GrpHdr.MsgId already imported, idempotency short-circuit

API endpoints touched

Upload: POST /v1/bank-accounts/:id/statements (multipart, ≤ 50 MB)
Poll: GET /v1/camt-statements/:id
Both requireOrgAdmin.

GDPR posture

Raw XML PUT into the bank-statements private bucket at {org_id}/camt053/{yyyy}/{mm}/{filename} before any processing — even rejected files land at …/rejected/… for 10-yr audit. Operator's name + timestamp captured in audit_logs per §7.bis.

Accessibility

Drop zone is a button (role="button", aria-label); click + Enter both trigger the file picker. Status pill row uses aria-live="polite" so a screen reader announces each transition. Cancel button keyboard-reachable during upload.
