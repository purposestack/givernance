Unreconciled queue

Cross-bank-account view of every credit entry the reconciler couldn't match cleanly. The operator's primary workspace for QR-bill exceptions.

Four reasons (§5.1 + §5.4)

invalid_ref — QRR mod-10 or SCOR mod-97 check failed
no_match — ref valid but not in swiss_qr_references (manual donation? wrong campaign?)
no_debtor_info — door-drop rail, debtor block missing/anonymised (TWINT, néo-banques)
orphan_reversal — RvslInd=true but no original donation row to reverse

Three resolutions (§6 perms)

link_to_existing · create_constituent_and_donation · write_off. All require requireWrite (accountant role suffices — not org_admin-only).

API endpoints touched

GET /v1/camt-unreconciled (paginated, filterable)
POST /v1/camt-unreconciled/:id/resolve (body: { resolution, donationId? | newConstituent? | writeOffNote })
POST /v1/camt-unreconciled/bulk-write-off (planned · accepts a filter selector + reason).

GDPR posture (§7, §5.5)

Debtor IBAN masked to last 4. Pre-filled "Create constituent" form shows the full structured Dbtr block extracted from RltdPties.Dbtr — operator sees PII because they have requireWrite. Constituent created with dataSource='camt053' + computed identityCompleteness per §5.5.

Bulk write-off (§3 future-work caveat)

The bulk-write-off action is gated on the active reason chip — operator cannot bulk-write-off across mixed reasons in one move. Forces an explicit reason per batch for the audit log (action=write_off).

Empty state

"No unreconciled credits — every camt.053 entry matched cleanly" with a quiet smile. Not aspirational ("great job!") — calm + factual per design north star.
